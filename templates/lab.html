What this proves

Two scheduler jobs each ask process_sale for stock, scheduled to start together. If the two requests add up to more than is on the shelf, exactly one can win. The row lock inside process_sale makes the second session wait, then re-read the real stock and be turned away cleanly.

Without that lock both sessions would read the same starting number and both would sell.
